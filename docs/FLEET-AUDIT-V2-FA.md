# نامزد OP-01 — ممیزی فقط‌خواندنی ناوگان VazinCMS

**وضعیت: CANDIDATE — جایگزین گیت فعلی Production نشده است.**

فایل `scripts/fleet_audit_v2.py` برای محیط staging و ممیزی مبتنی بر سیاستِ مستقل هر نصب است. اسکریپت `deploy/fleet-audit.sh` فعلی دست‌نخورده می‌ماند تا نسخه‌های هدف و قرارداد سرویس‌ها تأیید شوند. این ابزار تغییری در فایل، سرویس، DNS، دیتابیس یا وضعیت نصب‌ها ایجاد نمی‌کند.

## قرارداد ناوگان

برای هر نصب چهار عنصر *مستقل* تعیین می‌شود: دامنه دارای HTTPS، ریشه فایل نسخه همان نصب، `release_version` و قرارداد واقعی `/health` شامل `health_service` و `health_version`. فایل `MANIFEST.sha256` نیز باید دارای اثر انگشت مورد تأیید مستقل باشد. **نسخه مشاهده‌شده به‌صورت خودکار نسخه هدف نیست.** فهرست مسیرهای واقعی سرور خصوصی است و نباید وارد GitHub عمومی شود.

نمونهٔ نمایشی و غیرقابل‌استفاده برای Production:

```json
{
  "schema": 1,
  "policy_state": "candidate",
  "sites": [{
    "id": "example-site",
    "host": "cms.example.org",
    "root": "/srv/example-site/current",
    "release_version": "10.30.2",
    "health_service": "VazinCMS",
    "health_version": "10.30.2",
    "manifest_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  }]
}
```

## اجرای کاندید و قاعده تأیید

```bash
python3 scripts/fleet_audit_v2.py --policy /private/fleet-policy.json
python3 -m unittest discover -s tests -p 'test_fleet_audit_v2.py' -v
```

نسخه `candidate` در هر شرایطی `NO_GO` و کد خروج `70` می‌دهد. صرفاً تغییر فیلد `policy_state` از `candidate` به `approved` **مجوز انتشار نیست**. پس از بازبینی نسخه هدف، مالک سامانه باید SHA-256 فایل سیاست تأییدشده را از **مسیر مستقل و مورد اعتماد** به مرحله کنترل ارائه کند:

```bash
python3 scripts/fleet_audit_v2.py \
  --policy /private/approved-fleet-policy.json \
  --approved-policy-sha256 "$OWNER_APPROVED_POLICY_SHA256"
```

این دستور تنها زمانی کد خروج `0` می‌دهد که فیلد سیاست `approved`، اثر انگشت مستقل سیاست، نسخه فایل، قرارداد HTTPS health، اثر انگشت Manifest و تمام هش‌های فایل‌های هر سایت درست باشند. اگر یکی از این شرط‌ها شکست بخورد، خروجی JSON شامل `NO_GO` با کد `70` است. این ابزار **تأیید امضای بسته یا تمرین بازیابی نیست** و آن‌ها باید جداگانه انجام شوند. سیاست مورد تأیید باید دارای زنجیره approval خارج از کنترل خود فایل JSON باشد.

## نکات خاص شش نصب تاریخی

در ممیزی ۹ اکتبر ۲۰۲۶، نصب اصلی نسخه CMS `10.30.2` و چند نصب دیگر `10.29.0` داشتند. سرویس health سایت Travel با نام `Vazin Travel` و نسخه `1.0.0` پاسخ می‌داد و مستقل از نسخه CMS است. این اعداد صرفاً وضعیت مشاهده‌شده‌اند، نه حکم ارتقای همه نصب‌ها.

در همان ممیزی، `russiafa.ru` دارای ۱۸۱ اختلاف فایل با Manifest بود. پیش از هرگونه تأیید، باید منشأ انتشار و تفاوت فایل‌ها بررسی شود؛ **اسکریپت هیچ فایل یا Manifest را بازسازی نمی‌کند**. اقدام به rollout، تغییر فایل جاری یا rollback بدون تطبیق با پروژه RussiaFa ممنوع است.

## محدودیت‌ها

- ممیزی تنها فایل‌های *نام‌برده* در Manifest را پوشش می‌دهد؛ نبود فایل اجرایی اضافه را مستقلاً اثبات نمی‌کند.
- صحت یک Manifest فقط در صورت اعتماد به fingerprint مرجع معنا دارد؛ این ابزار release signature را بررسی نمی‌کند.
- انجام عملیات انتشار و بازگشت نسخه تنها با مسیرهای جداگانه و تأییدشده مجاز است.
- برای جلوگیری از افشای ساختار داخلی، Policy واقعی، مسیرهای سرور، و فایل‌های محیطی وارد مخزن عمومی نشوند.
