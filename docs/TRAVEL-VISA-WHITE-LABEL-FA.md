# راه‌اندازی پلتفرم وایت‌لیبل سفر و ویزا

## مرز محصول

هر نصب VazinCMS یک tenant مستقل برای یک کسب‌وکار دارای مجوز است. برند، دامنه،
حساب پرداخت، credential تأمین‌کننده، دادهٔ مسافر و bot Telegram هر آژانس باید
در همان نصب بماند. این محصول به‌خودی‌خود فروشندهٔ بلیت، هتل یا ویزا نیست.

## حالت‌های قابل‌فعال‌سازی

- `lead_only`: درخواست مشتری به اپراتور آژانس می‌رسد.
- `affiliate_redirect`: فقط ارجاع مجاز و شفاف به شریک تأییدشده.
- `manual_fulfilment`: اپراتور آژانس خارج از سیستم یا با ابزار قراردادی کار را
  انجام می‌دهد.
- `live_booking`: فقط پس از قرارداد، adapter اختصاصی، credential رمزنگاری‌شده،
  revalidation و آزمون sandbox.

رکورد `/admin/travel-connectors` هیچ اتصال شبکه‌ای ایجاد نمی‌کند و به‌تنهایی
اجازهٔ فعال‌سازی فروش زنده نیست.

## eVisa

مسیر عمومی `/{locale}/visa` ابتدا یک پروندهٔ دستی صفرقیمت باز می‌کند؛ نه محصول
نهایی می‌فروشد، نه فاکتور یا checkout می‌سازد و نه وعدهٔ صدور خودکار می‌دهد.
پس از ایجاد session و کد پیگیری، فرم کامل eVisa باز می‌شود. اپراتور باید مقصد،
تابعیت، نوع ویزا، checklist، زمان بررسی و مسئولیت قانونی را برای همان آژانس
تعیین کند. دادهٔ حساس رمزنگاری‌شده است، به مشتری پس از ثبت بازگردانده نمی‌شود
و فقط owner/admin مجاز با پاسخ no-store آن را می‌بیند.

`VAZIN_VISA_DIRECT_SALES_ENABLED=false` باید تا زمان قرارداد فروشندهٔ دارای
مجوز، هویت حقوقی، review پرداخت و آزمون کنترل‌شده false بماند. در این وضعیت
callback پرداخت هم fail-closed است و پاسخ `410` می‌دهد.

## Telegram

1. ربات و Webhook اختصاصی tenant را در `/admin/telegram` ثبت و در staging
   بررسی کنید.
2. فقط بعد از تأیید متن رضایت و آزمون، سه gate زیر را فعال کنید:

   ```env
   EXTERNAL_DELIVERY_ENABLED=true
   TELEGRAM_NETWORK_ENABLED=true
   TELEGRAM_ALERT_DELIVERY_ENABLED=true
   ```

3. مدیر از `/admin/travel-alerts` پیوند یک‌بارمصرف می‌گیرد و شخصاً ربات را
   Start می‌کند.
4. مشتری از صفحهٔ پرونده خودش به‌صورت اختیاری opt-in می‌کند.

اگر هر مورد لغو شد، gate را false کنید یا اتصال را غیرفعال کنید. برای لغو
کاربر، `/stop` در همان ربات کافی است.

## قبل از فروش زنده

- قرارداد امضاشده و مسئول فروش/صدور هر منبع مشخص شده باشد.
- adapter موردنظر `search → quote → revalidate → book → issue → cancel/refund`
  را فقط در قابلیت‌های واقعی خودش اعلام کند.
- نرخ نهایی، فروشندهٔ حقوقی، قوانین لغو، زمان آخرین revalidate و مسیر پشتیبانی
  در UI آژانس مشخص باشد.
- یک رزرو sandbox یا canary غیرمالی، سپس reconciliation عملیاتی انجام شود.
