# OP-02.10 — آزمون خصمانهٔ ایزولهٔ Nginx real_ip و اولویت Location

**۱۵ اکتبر ۲۰۲۶ | وضعیت نامزد: DRAFT / Production: NO-GO**

این سند شاهد یک **آزمون آزمایشگاهی عمدی** است؛ نه توصیف پیکربندی سایت‌های فعال و نه دستور اجرای تغییر عملیاتی. در OP-02.8/9 مسیرهای نمونهٔ HTTP و تنظیمات curl سخت‌گیرانه‌تر شده بودند، اما همچنان پوشش کامل همهٔ endpointها ثابت نشده است.

## محدوده و مرزهای ایمنی

- اسکریپت: 'tests/integration/isolated_nginx_fence_realip_adversarial.py'.
- فقط روی Nginx مستقل با یک پیکربندی تازه زیر TemporaryDirectory و 'listen 127.0.0.1:PORT' غیرمجاز برای Production اجرا می‌شود؛ پورت به‌صورت محلی و پویا تعیین می‌شود و پورت‌های 80 و 443 استفاده نمی‌شوند.
- '-p' به دایرکتوری موقت اشاره می‌کند؛ '-c conf/nginx.conf' فقط پیکربندی همان فرایند تست است؛ 'daemon off; master_process off;' برای کنترل دقیق همان فرایند آزمایشی به‌کار می‌رود.
- فقط توکن **مصنوعی** استفاده می‌شود، نه توکن Fence واقعی، نه حساب tenant، نه FPM/DB، نه شبکهٔ عمومی و نه فایل‌های vhost اصلی. پایان هر سناریو فقط فرایند ایجادشده توسط اسکریپت را خاتمه می‌دهد.
- پاسخ QA به‌وسیلهٔ 'return 200' در Nginx **شبیه‌سازی** می‌شود. این تست مسیر FastCGI/نسخهٔ واقعی CMS، TLS/SNI و 'real_ip' واقعی سایت‌های Production را **تأیید نمی‌کند**.
- این اسکریپت به‌عمد فقط دستی اجرا می‌شود، نه به‌عنوان تست یکپارچگی فعال پیش‌فرض CI. تست‌های Python قرارداد فایل و ایمنی ساختار آن را بررسی می‌کنند.

## سناریوهای بازتولیدشده در S17

| سناریو | انتظار آزمایشگاهی | مشاهده |
|---|---|---|
| منبع اتصال '127.0.0.2'، بدون XFF و با توکن ساختگی صحیح، گیت سست | 503 | PASS |
| همان اتصال، 'X-Forwarded-For: 127.0.0.1'، گیت سست مبتنی بر '$remote_addr' | 200 = **نشان دادن ضعف عمدی** | PASS |
| همان جعل XFF، گیت سخت‌گیرانه مبتنی بر آدرس اصلی حمل‌ونقل | 503 | PASS |
| اتصال واقعی از '127.0.0.1' + توکن صحیح + GET خصوصی | 200 | PASS |
| توکن اشتباه/بدون توکن، POST خصوصی، XFF زنجیره‌ای یا منبع غیرمجاز | 503 | PASS |
| نمونه‌های عمومی شناخته‌شده و Canary زیر Fence صحیح | 503 + fingerprint + no-store | PASS |
| استثنای 'location ^~ /assets/' عمداً ناامن | 200 = **اثبات شکست استثنای مسیر** | PASS |
| استثنای regex برای '.php' خارج از مسیرهای ثابت | 200 = **اثبات ضعف نمونه‌گیری** | PASS |
| استثنای exact برای '/unmodeled-admin-action'، در حالی که همهٔ نمونه‌های عمومی و Canary به 503 پاسخ می‌دهند | 200 = **اثبات ناکافی‌بودن پوشش نمونه‌ها** | PASS |

**تفسیر درست:** PASS در حالت‌های ناامن یعنی سناریوی **آسیب‌پذیرِ ساختگی** طبق انتظار پاسخ 200 داد؛ به‌معنی امن‌بودن آن نیست. در آزمایش XFF، توکن صحیح **عمداً** در اختیار شبیه‌ساز حمله قرار گرفته تا مستقل‌بودن شرط IP از محرمانه‌بودن توکن سنجیده شود. **این به‌هیچ‌وجه اثبات دسترسی مهاجم بدون توکن در سایت واقعی نیست.**

در آزمایش، '127.0.0.2' نقش یک peer آزمایشگاهیِ غیرمجاز را دارد. نمی‌توان آن را با یک مهاجم اینترنتی واقعی یا پیکربندی زنجیرهٔ CDN/Proxy سایت‌های موجود یکی دانست. '$realip_remote_addr' پس از rewrite آدرس transport را نگه می‌دارد، ولی حتی الگوی آزمایشگاهی مبتنی بر آن بدون ممیزی دقیق تمام trust boundaryها، مسیرهای proxy محلی، upstreamها و هویت token برای Production قابل کپی‌کردن نیست.

## روش اجرای کنترل‌شدهٔ آزمایش

فقط در clone آزمایشی مجزا و یک میزبان دارای Nginx با ماژول realip:

    python3 tests/integration/isolated_nginx_fence_realip_adversarial.py

نتیجهٔ موفق باید حاوی 'ISOLATED_NGINX_ADVERSARIAL_PASS' و 'production: "NO_GO"' باشد. شکست آزمایش با 'NO_GO ISOLATED_REHEARSAL_FAILED' و exit code 70 پایان می‌یابد. **نباید** آزمون را با پورت Production، فایل توکن واقعی یا سرویس Nginx اصلی اجرا کرد.

## چک‌لیست ممیزی مستقل پیش از Production

۱. تمام 'server'/'location' و includeهای vhost هدف، اولویت '=', '^~', '~', '~*', prefix, rewrite/alias/try_files/error_page/internal redirect, روش‌های HTTP، مسیرهای وب‌هوک/پرداخت و مسیرهای ایجاد side effect باید توسط بازبین انسانی بررسی شوند. پاسخ 503 به مسیرهای نمونه، جایگزین این ممیزی نیست.

۲. تنظیمات 'set_real_ip_from', 'real_ip_header', 'real_ip_recursive', شبکهٔ reverse proxy/CDN، مقادیر 'X-Forwarded-For', PROXY protocol، IP واقعی transport، SNI و Host مستقل بررسی شوند. 'X-Forwarded-For' ارسال‌شده از طرف کاربر هرگز به‌خودی‌خود مجوز loopback نیست.

۳. مسیر خصوصی '/__vazin_cms_health' فقط برای GET، فقط با مجوز اتصال محلی قابل‌اتکا و اثر صحیح توکن خصوصی، و فقط برای Health همان runtime انتخاب‌شده معتبر باشد. توکن نباید در argv، Git، لاگ یا پاسخ عمومی ظاهر شود. اثرانگشت عمومی به‌تنهایی مجوز QA نیست.

۴. درخواست‌های آغازشده پیش از فعال‌شدن Fence و workerهای مستقل PHP-FPM باید واقعاً drain شوند. سرویس مشترک Travel/Visa، background jobs، cron و webhook writers مانع مهم فعلی‌اند؛ زمان‌انتظار ثابت یا 503 عمومی کافی نیست.

۵. تأییدهای جداگانهٔ tenant identity، OAuth/پرداخت، OPcache، Restore بکاپ، RPO/RTO، امضا و مجوز صریح مالک الزامی‌اند. شواهد این فایل به هیچ‌کدام اعتبار Production نمی‌دهد.

۶. هنگام ممیزی read-only پیکربندی واقعی، به‌علت احتمال وجود secrets در 'nginx -T' یا includeها، خروجی خام به چت عمومی، لاگ کنترل‌نشده یا مخزن Git ارسال نشود؛ شواهد از ابتدا با رویکرد کمینه‌سازی داده و redaction تهیه شوند.
