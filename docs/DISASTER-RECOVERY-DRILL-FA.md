# تمرین بازیابی ایزوله VazinCMS — راهنمای OP-03

**وضعیت:** راهنمای آزمون؛ این سند مجوز تغییر Production یا اثبات کامل Disaster Recovery نیست.

## هدف و محدودیت ایمنی

تمرین باید نشان دهد نسخهٔ پشتیبان واقعی می‌تواند در محیطی جدا از سایت و دیتابیس زنده، به یک برنامهٔ قابل‌پاسخ‌گویی تبدیل شود. محیط باید مسیر، پورت، حساب‌های آزمایشی و تنظیمات مستقل داشته باشد. نه روی سایت زنده restore کنید، نه DNS، سرویس‌های عملیاتی، کلیدها، پرداخت‌ها یا Jobهای کاربران را تغییر دهید.

پیش از آزمون:
1. موجودی و تاریخ snapshot، منبع معتبر، هویت نسخه و SHA-256 چهار جزء اصلی (کد، Storage، دیتابیس، محیط) را کنترل کنید. صحت checksum جایگزین اعتبارسنجی مستقل منشأ یا امضای بسته نیست.
2. اعضای آرشیو را پیش از استخراج بررسی کنید: مسیر مطلق، traversal با «..»، symlink/hardlink و device file باید رد شوند.
3. محیط موقت با دسترسی محدود و فضای کافی ایجاد کنید؛ منبع Production باید فقط‌خواندنی بماند.
4. فقط پیکربندی **ساختگی** برای آزمون برنامه بسازید؛ فایل environment.original را به وب‌سرور آزمایشی ارائه ندهید و محتوای محرمانهٔ آن را در لاگ یا گزارش ننویسید.
5. ارتباطات بیرونی (Telegram، ایمیل، webhook، پرداخت و فروش مستقیم) باید غیرفعال باشند؛ redirectها را بدون دنبال‌کردن ثبت کنید.

## گام‌های ارزیابی

- Code archive و Storage را پس از اعتبارسنجی به ریشهٔ ایزوله استخراج و دیتابیس snapshot را در همان ریشه بازیابی کنید. اجرای واقعی را به نسخه زنده یا دیتابیس آن وصل نکنید.
- برای SQLite، integrity_check و foreign_key_check را روی نسخه بازیابی‌شده انجام دهید؛ نسخه، تعداد جدول‌ها و migrationها را ثبت کنید. برای PostgreSQL، تمرین مستقل و ابزار مناسب لازم است.
- دستور syntax-check PHP را روی کد بازیابی‌شده اجرا کنید.
- یک HTTP listener موقت صرفاً روی 127.0.0.1 با متغیرهای محیطی ساختگی اجرا و درخواست‌های زیر را بدون دنبال‌کردن redirect و بدون ارسال اطلاعات واقعی امتحان کنید:

| مسیر | معیار آزمون |
|---|---|
| /health | HTTP 200، ok=true، نسخه مورد انتظار |
| / و /fa | HTTP 200 |
| /login | HTTP 200 و فرم ورود |
| /admin (بدون ورود) | HTTP 302 به /login |
| /docs | HTTP 200 |
| /api/openapi.json | HTTP 200 و JSON معتبر |

- تمام فرایندهای آزمایشی را متوقف کنید و حذف محیط موقت را بررسی کنید. کد خروج و مقادیر غیرحساس را در رسید ثبت کنید.

## شواهد آزمون ۱۰ اکتبر ۲۰۲۶

در یک تمرین روی snapshot رسمی همان روز، checksum چهار فایل PASS، SQLite integrity برابر ok، foreign_key_check برابر ۰، تعداد migration برابر ۷۰ و نسخه برابر 10.30.2 بود. Code و Storage در محیط موقت بازیابی شدند؛ PHP مستقل، /health، صفحه عمومی، فرم /login، redirect محافظت‌شده /admin، مستندات و JSON مربوط به OpenAPI مطابق معیارهای بالا پاسخ دادند. تنظیمات Production استفاده نشد، فرایند آزمایشی متوقف و محیط موقت پاک شد.

**سطح پذیرش:** ISOLATED_APPLICATION_RESTORE_PASS؛ این نتیجه، بازیابی سیستم واقعی با Nginx/TLS، اتصال دامنه، رسانه واقعی مشتری، ورود موفق و RBAC، سنجش RPO/RTO توافقی، مانیتورینگ، سرویس‌های بیرونی یا disaster recovery چندسایتی را ثابت نمی‌کند.

## گیت باقی‌مانده پیش از انتشار

تأیید نهایی OP-03 به تمرین کنترل‌شده در staging اختصاصی، راستی‌آزمایی تمام داده‌ها/رسانه‌های پشتیبان، تست احراز هویت با حساب آزمایشی، کنترل گواهی و routing، تعریف و سنجش RPO/RTO، نظارت و مستندسازی rollback نیاز دارد. شکست هر کنترل مهم، NO-GO است. این سند نباید به تنهایی گیت OP-11 را آزاد کند.

**حفاظت اطلاعات:** مسیرهای خصوصی سرور، محتوای .env، credential، شناسه‌های کاربر، دیتابیس و لاگ خام محرمانه را در مخزن عمومی قرار ندهید.

## تکمیل شواهد بازیابی ایزوله — ۱۰ اکتبر ۲۰۲۶

علاوه بر آزمون پیشین، نسخهٔ بازیابی‌شده با Nginx و PHP-FPM مستقل، روی `127.0.0.1` و TLS با گواهی ساختگی کوتاه‌مدت اجرا شد. اعتبار TLS با CA آزمایشی و کنترل hostname انجام شد و هفت مسیر `/health`، `/`، `/fa`، `/login`، `/admin`، `/docs` و `/api/openapi.json` مطابق قرارداد پاسخ دادند. مشکل اولیهٔ انتقال‌نیافتن محیط PHP-FPM در پیکربندی آزمایش رفع و اجرای مجدد موفق شد؛ تنظیمات واقعی سرویس‌ها تغییر نکردند.

در تمرین احراز هویت، تنها **کپی موقت دیتابیس** برای ورود با گذرواژهٔ ساختگی آماده شد. درخواست `/admin` پیش از ورود به `/login` هدایت شد؛ ارسال فرم همراه CSRF پاسخ 302 به `/admin` داد و بازدید بعد از ورود پاسخ 200 گرفت. هیچ رمز، حساب، نشست یا فایل دیتابیس واقعی تغییر نکرد. سرویس‌های موقت متوقف و محیط‌های بازیابی حذف شدند.

**سطح نتیجه:** `ISOLATED_STACK_AND_SYNTHETIC_AUTH_PASS`؛ هنوز بازیابی با TLS/DNS واقعی، ورود کاربران واقعی، رسانه کامل، سرویس‌های خارجی، اثبات RPO/RTO هدف و سناریوی کامل فاجعه در Production احراز نشده‌اند. گیت نهایی انتشار همچنان `NO_GO` است.
