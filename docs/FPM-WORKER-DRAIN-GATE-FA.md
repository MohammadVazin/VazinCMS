# OP-02.3 — ممیزی فقط‌خواندنی Drain و PHP-FPM

**وضعیت:** CANDIDATE / NO-GO. این ابزار به‌هیچ‌وجه مجوز انتشار نیست.

## چرا لازم است؟

Fence عمومی Nginx در بهترین حالت جلوی **درخواست‌های تازه** را می‌گیرد؛ تضمین نمی‌کند درخواست‌هایی که پیش از Maintenance وارد PHP-FPM شده‌اند، تمام شده باشند. در آزمایش ایزوله، پس از آنکه درخواست تازه HTTP 503 گرفت، یک درخواست PHP قدیمی هنوز موفق شد روی فایل آزمایشی بنویسد و با HTTP 200 تمام شود.

برای ارتقای امن باید **درخواست‌های قدیمی و Workerهای پس‌زمینه** نیز با سند قابل‌راستی‌آزمایی به وضعیت امن رسیده باشند. صرف انتظار ثابت یا دریافت پاسخ 503 از یک سایت، این شرط را اثبات نمی‌کند.

## ابزار ممیزی اولیه

دستور نمونه:
    python3 scripts/fpm_drain_inventory.py --hosts travel.vazin.online visa.vazin.online studio.vazin.online

این اسکریپت فقط متن پیکربندی Nginx و Poolهای PHP-FPM موجود را **می‌خواند**؛ به سوکت‌ها وصل نمی‌شود، شبکه را تغییر نمی‌دهد و هیچ سرویس یا Jobی را متوقف نمی‌کند. ابزار، مالکیت مشاهداتیِ FastCGI upstream، مشترک یا اختصاصی‌بودن نام سوکت، وجود تنظیم pm.status_path و شکاف شواهد را به‌صورت JSON نمایش می‌دهد.

**تصمیم همیشه NO_GO با کد ۷۰ است**؛ زیرا ممیزی استاتیک نمی‌تواند ثابت کند درخواست‌های درحال اجرا، صف PHP، قفل‌های دیتابیس، Cron و Jobهای صف تمام شده‌اند. حتی pm.status_path پیکربندی‌شده هم بدون مشاهدهٔ معتبر، بازهٔ پایدار و تطبیق مستقل شناسهٔ Pool، کافی نیست.

## مشاهدهٔ ۱۰ اکتبر ۲۰۲۶

در خوانش فقط‌خواندنی S17، Travel و Visa هر دو از Pool عمومی www و سوکت php8.5-fpm.sock استفاده می‌کردند. پیکربندی‌های Nginx خوانده‌شده این سوکت را برای **۱۷ نام میزبان** نشان می‌دادند؛ این عدد حاصل شمارش استاتیک است و لزوماً تعداد واقعی سایت‌های فعال یا درخواست‌های جاری نیست. Studio از Pool مستقل vazincms-studio استفاده می‌کرد. برای هیچ‌کدام از دو Pool، مسیر pm.status_path در تنظیمات خوانده‌شده وجود نداشت.

تمام این موارد قابل بازبینی‌اند، اما **عدم مشاهدهٔ Worker فعال به معنی صفر بودن Worker فعال نیست**؛ این ابزار اصلاً وضعیت زندهٔ Workerها را نمی‌خواند.

## الزامات پذیرش آینده

- شناسایی معتبر و مستقل همهٔ endpointهای عمومی، مسیرهای Webhook و Jobهای زمان‌بندی‌شده برای سایت هدف
- جداسازی Poolها یا ایجاد روش اثبات هویت درخواست/Worker هر سایت هنگام استفاده از Pool مشترک
- Fence واقعی با صحت TLS و مسیرهای عمومی، سپس تأیید تخلیهٔ درخواست‌های قدیمی و صف‌ها طی بازهٔ معتبر
- توقف امن دریافت کار جدید و اطمینان از عدم ایجاد نوشتن جدید توسط Workerهای قدیمی هنگام Swap
- مانیتورینگ Health سایت‌های همسایه؛ تمرین Fault Injection و قابلیت Rollback بدون توقف سراسری
- تأیید مستقل مالک، رسید پذیرش، حفظ داده و تعریف RTO/RPO پیش از انتشار

تا تکمیل این شروط، استفاده از Installer نامزد برای S17 **ممنوع** است. نباید با افزودن یک فایل JSON خوداظهاری یا تغییر رشتهٔ Health، گیت را سبز جلوه داد.
